# Contributing

Contributions are welcome.

## Principles

- Keep security boundaries explicit.
- Prefer small, reviewable changes.
- Do not commit credentials, tokens, private repository content, or production configuration.
- Add tests for behavioral changes.
- Document externally visible architecture or configuration changes.
- Avoid coupling generic control-plane code directly to a specific AI provider.

## Development flow

1. Create an issue or describe the problem being solved.
2. Create a focused branch.
3. Implement the smallest coherent change.
4. Run relevant tests and static checks.
5. Review the Git diff for generated or sensitive files.
6. Open a pull request describing the change, rationale, and validation.
